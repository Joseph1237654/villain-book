# 旧版复盘与本次决定

首次重建检查日期：2026-11-14。检查对象：替换前的原仓库内容，现可通过 Git 历史回查。本文件记录编辑判断，不代表对旧稿作者或读者的评价。

## 一、实际看到了什么

旧版已经具备构建脚本、自动化测试、双语编目、序和导论，以及方源、魂天帝、万磁王三篇人物样稿。它不是没有工作量，主要问题是工作先后和书的主线还没有对齐。

首次重建开始时，旧版 Git 工作区干净，v2 为空。旧版已配置 GitHub 远端；该阶段只在 v2 创建新稿，未改动原仓库。

## 二、为什么读起来不够扎实

### 人物名单过早变成结构

旧版将四位网文人物、五位漫画人物组成的九人名单视为固定版本，而且构建检查强制要求九章。这会让后续研究迁就人数，而不是根据问题决定材料。唐三没有进入该名单。

旧版有“用户确认的九人名单”之类表述。本次可见对话只明确给出了古月方源、韩立、唐三作为例子，因此 v2 不沿用那项授权声明，也不据此断言旧版从未有过其他讨论。

### 分析框架重叠，正文容易重复

五种特质之后又有四种力量，再有两道检验和六节章法。每套都能说通，合起来却容易让一章忙于完成表格。

人物稿中出现不少关于目标、坚持、边界的总体解释，但原作场景的定位较少。读者可以同意结论，却难以核查它究竟如何从具体选择中得出。

### 书名的落点还没有成为阅读过程

旧稿重视不替恶行开脱，这一点值得保留。但如果每个人物都落在近似的边界提醒上，人物之间的差别和读者自己的行动问题会被压缩。

v2 要让代价与纠错进入具体分析：坏消息怎样被忽略，一次退让保住了什么，一项承诺又让谁失去选择。这样才有条件谈自由与理性。

### 出版规格先于正文

中文论证还需要寻找声音时，双语同步和多格式出版增加了额外工作。构建通过可以证明文件合规，不能证明解释有说服力。

## 三、本次采用的重建方式

| 决定 | 原因 |
| --- | --- |
| 独立写在 v2 | 保留旧稿和历史，方便比较 |
| 先按问题编排 | 让人物围绕同一个选择相互检验 |
| 核心样本从用户点名的三人起步 | 研究范围可追溯，不代替用户扩成固定名单 |
| 先中文、先 Markdown | 让精力集中在材料与论证 |
| 先试写三个不同领域的章节 | 检验方法能否写出差异，再扩成长书 |
| 人物卡记录假设与反例 | 防止流行标签提前决定文章 |
| 引文和场景分别定位 | 读者能够复核作者是怎样得出结论的 |

这些是本轮实施的工作假设。目录、文风和后续技术方案仍可以根据实际阅读反馈调整。

## 四、旧版有哪些东西可以以后再取

可参考其构建器、格式测试、术语整理方法，以及对合作和纠错的关注。真正复用技术前，再评估是否适合新结构，不原样继承九章限制和双语强制条件。

旧版的人物论断可以作为研究问题，不能未经核对就变成新稿中的事实。

## 五、整体替换的后续决定

首次重建后，用户明确要求将本次 v2 的全部内容推送到原远端，删除当前版本中的原有文件并以新版整体替换。

因此，本次发布采用原仓库的 `main` 分支和 Git 历史，将当前文件树替换为 v2。原版正文、目录、构建器与测试不再混入新版；需要查看时可回查历史提交。本地 `villain-book-v2` 仍保留为重建稿的工作副本。

该决定取代首次重建阶段“不改原仓库、不提交、不推送”的执行范围，不改变对旧版内容的编辑复盘。
